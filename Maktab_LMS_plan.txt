--------------------

ishlash uchun nusxalab yuboriladigan promptlar to‘plami.
15 mavzuli dars, 90 asosiy prompt + 6 ta operator API va 2 ta deploy/storage prompti = 98 amaliy
prompt. P000 - ularni boshqaradigan umumiy ko‘rsatma, 98 hisobiga kirmaydi.

frontend yil, sinf yoki enrollment yaratish uchun DB/seedga muhtoj bo‘lmaydi.

Avval P000ni yuboring. Keyin mundarijadagi tartibda faqat bitta prompt yuboring.
Oldingi promptning qabul mezonlari tekshirilgach keyingisiga o‘ting. P023dan keyin
P023-A, B, C, D, E, F; undan so‘ng P024. P081dan keyin P081-A, P081-B;
undan so‘ng P082. Qolganlari raqam bo‘yicha.
Yangi chat yoki kontekst yo‘qolganda P000 va docs/backend-progress.mdni bering,
so‘ng birinchi tugamagan promptni yuboring. Butun TXTni bir martada bajarishni
so‘ramang. Mavjud repositoryga moslansin, har safar yangi loyiha ochmasin.

Har bir PROMPT BOSHI ... PROMPT OXIRI bloki birgalikda ko‘chiriladi. Uning ichida:

O‘QITISH RITMI
--------------
Har promptda: tushuncha > kichik misol > cheklangan kod > API tekshiruvi > izoh.
Bitta prompt odatda 15-40 daqiqa; concurrency, scan, restore yoki deploy ko‘proq
vaqt oladi. 15 dars - mavzuli guruhlash; har guruhning hamma prompti qat’iy
3 soatda tugaydi degan va’da emas. Takroriy test/CI va ayrim amaliy ishlar uyga
berilishi mumkin. Frontend olib tashlangani vaqtni backendni chuqurroq o‘rganish,
HTTP client va testlarga ajratadi.

Bir vaqtning o‘zida stackning hammasini o‘rnatmang. “Yangi dependency” shu
bosqichda nimani qo‘shishni ko‘rsatadi; mavjud mos paket qayta o‘rnatilmaydi.
Avval u nima, qaysi muammoni hal qiladi va nega kerakligi tushuntiriladi.

ARXITEKTURA KELISHUVI
--------------------
- Bir maktab; role faqat pupil/teacher. manage_accounts/manage_academics -
  tanlangan teacher capabilitylari; Django superuser texnik vosita.
- Accounts, academics, learning, files, assignments, assessments, scheduling,
  communications, core va ai kabi app faqat ehtiyoj bosqichida ochiladi.
- User birinchi migrate’dan OLDIN custom qilinadi. DB/historyni reset qilish yo‘q.
- Session auth bosh tanlov: Django CSRF-himoyalangan login/logout. Kelajak
  same-origin frontend /api/ orqali ishlaydi; JWT/CORS wildcard shart emas.
- Global IsAuthenticated; list scope, detail permission, writable parent FK
  validation va service biznes qoidalari birgalikda ishlaydi.
- Oddiy CRUD - generics/mixins/ViewSet; workflow - tor action + service;
  agregatsiya - output Serializer bilan APIView/GenericAPIView.
- UTC aware datetime, mahalliy maktab zonasi Asia/Tashkent; Decimal ball.
- Bahoning totalini server hisoblaydi; question kaliti pupil payloadga kirmaydi.
- Published kontent/rubric va submitted revision izsiz overwrite qilinmaydi.
- Private fayl bytes storage’da, metadata DBda. Clean bo‘lmagani ochilmaydi.
- Transaction muhim DB amallarida; broker ishonchliligi outbox + idempotent
  consumer. Bitta Beat; cache brokerdan productionda ajratiladi.
- Faqat sintetik test ma’lumoti. Secret, login body, session va pupil matni logga
  yozilmaydi. Zarur audit minimal model sifatida birinchi real ehtiyojda qo‘shiladi.
- Error contract yakuni: code/message/fields/request_id. 409 kerak bo‘lsa tor
  custom APIException yaratiladi/reuse qilinadi; katta framework yozilmaydi.
- Ommaviy parent o‘zgartirish/delete tarixni buzmasin; yopiq termga write gate
  keyingi topic/assignment/grade servicelariga ham tatbiq qilinadi.
- Published assignment deadline o‘zgarishi audit va deadline_version bilan;
  rubric/shart boshqa qoidada immutable. End-to-end fake scan real emas.
